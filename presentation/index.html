1. Project Overview

Face Scanner is a Python-based biometric authentication system that uses face recognition combined with liveness detection to prevent spoofing attacks. The system can register users and verify their identity in real-time using a webcam.

Key Highlights

  • ✅ Real-time face recognition using deep learning
  • ✅ Blink-based liveness detection to prevent photo spoofing
  • ✅ Motion detection to optimize performance
  • ✅ Visual feedback with color-coded access results
  • ✅ Persistent user database using pickle serialization

2. Project Objectives

🎯 Primary Goal

Create a secure access control system that can authenticate users based on facial recognition while preventing common spoofing attacks (photos, videos, masks).

🔒 Security Focus

Implement liveness detection to ensure only real, live faces can be authenticated, not static images or pre-recorded videos.

⚡ Performance

Optimize for real-time processing with motion detection to reduce unnecessary computational load.

👥 User Experience

Provide clear visual feedback and intuitive registration/authentication flow for end users.

3. System Architecture

Component Overview

Webcam Input - Captures video frames
Motion Detection - Filters frames with motion
Face Detection - Locates faces in frame (dlib)
Face Encoding - Converts face to 128D vector (face_recognition)
Face Matching - Compares with registered users
Liveness Check - Verifies blink detection (dlib landmarks)
Access Decision - Grants or denies access

Data Flow

Video Frame → Motion Detection → Face Detection → Encoding → Matching → Liveness → Decision

6. Code Walkthrough

Main Components

1. Eye Aspect Ratio (EAR) Calculation

def calculate_eye_aspect_ratio(eye_points: np.ndarray) -> float:
    """Calculate Eye Aspect Ratio for blink detection."""
    A = dist.euclidean(eye_points[1], eye_points[5])  # Vertical distance 1
    B = dist.euclidean(eye_points[2], eye_points[4])  # Vertical distance 2
    C = dist.euclidean(eye_points[0], eye_points[3])  # Horizontal distance
    ear = (A + B) / (2.0 * C)  # EAR formula
    return ear

Purpose: Measures eye openness. When EAR < 0.21, eyes are closed (blink detected).

8. System Workflow

Registration Workflow

User runs: python face_scanner.py --register username
System opens webcam and detects face
User must blink 2+ times (liveness check)
System captures 10 face encodings (when eyes open)
Encodings saved to users/username.pickle

Recognition Workflow

User runs: python face_scanner.py
System monitors webcam for motion
Motion detected → Face detection triggered
Face encoding extracted and compared with registered users
If match found (confidence ≥ 55%):
→ Liveness verification (blink required)
→ If blink detected: ACCESS GRANTED
→ If no blink: ACCESS DENIED
If no match: ACCESS DENIED (Unknown Face)

Security Measures

  • Photo Spoofing Prevention: Requires blinks during registration and recognition
  • Confidence Thresholding: Only matches with ≥55% confidence are considered
  • Multiple Encodings: Uses 10 face encodings per user for better accuracy
  • Real-time Verification: Liveness check happens during each authentication attempt

9. Face Storage Mechanism

What Gets Stored?

The system does NOT store actual face images. Instead, it stores face encodings - mathematical representations of facial features.

Storage Format

File: users/username.pickle
{
    'username': 'john_doe',
    'encodings': [
        [0.123, -0.456, 0.789, ...],  # 128-dimensional vector 1
        [0.125, -0.454, 0.791, ...],  # 128-dimensional vector 2
        ...                            # 10 total encodings
    ],
    'timestamp': 1704123456.789
}

Face Encoding Explained

  • 128-Dimensional Vector: Each face is converted to 128 numbers
  • Deep Learning Model: Uses ResNet architecture (pre-trained)
  • Unique Representation: Same person = similar vectors, Different person = different vectors
  • Cannot Reverse: You cannot reconstruct the face image from the encoding

Why 10 Encodings Per User?

Variation Capture

Captures different lighting, angles, expressions during registration

Better Accuracy

Multiple encodings improve recognition accuracy

Robust Matching

System compares against all 10 encodings, finds best match

Storage Location

users/
├── john_doe.pickle      # 10 encodings for John
├── jane_smith.pickle    # 10 encodings for Jane
└── admin.pickle         # 10 encodings for Admin

Privacy & Security

  • ✅ No Images Stored: Only mathematical vectors (128 numbers)
  • ✅ Cannot Reconstruct: Impossible to recreate face from encoding
  • ✅ Small Size: Each user file ~5-10KB (vs MB for images)
  • ⚠️ For Production: Should encrypt pickle files or use database

10. Recognition Process (Detailed)

Step-by-Step Recognition Flow

Step 1: Motion Detection

Capture current frame from webcam
Convert to grayscale and apply Gaussian blur
Calculate absolute difference with previous frame
If difference > threshold (25) → Motion detected

Purpose: Optimize performance - only process frames with movement

Step 2: Face Detection

Convert frame to RGB (face_recognition requires RGB)
Use face_recognition.face_locations()
Returns bounding box: (top, right, bottom, left)
Extract face region from frame

Technology: HOG (Histogram of Oriented Gradients) + Linear SVM

Step 3: Face Encoding

Use face_recognition.face_encodings()
Deep learning model (ResNet) processes face image
Outputs 128-dimensional vector
This vector represents unique facial features

What the encoding contains: Mathematical representation of facial geometry, texture, and features

Step 4: Face Matching

# Load all registered encodings
known_encodings = [encoding1, encoding2, ...]  # All users
known_names = ['john', 'jane', ...]

# Compare current face with all known faces
matches = face_recognition.compare_faces(
    known_encodings, 
    current_encoding, 
    tolerance=0.5
)

# Calculate distances
distances = face_recognition.face_distance(
    known_encodings, 
    current_encoding
)

# Find best match
best_match_index = argmin(distances)
confidence = 1 - distances[best_match_index]

Matching Algorithm Details

  • Euclidean Distance: Measures similarity in 128D space
  • Tolerance (0.5): Maximum distance to consider a match
  • Confidence: 1 - distance (higher = more similar)
  • Threshold (55%): Minimum confidence to grant access

Step 5: Liveness Verification

If match found (confidence ≥ 55%):
→ Detect facial landmarks (68 points) using dlib
→ Extract eye landmarks (points 36-47)
→ Calculate Eye Aspect Ratio (EAR)
→ Monitor for blink (EAR < 0.21 = closed)
→ If blink detected: ACCESS GRANTED
→ If no blink: ACCESS DENIED

Performance Metrics

  • Face Detection: ~50-100ms per frame
  • Face Encoding: ~50-100ms per face
  • Face Matching: ~1-5ms per comparison (depends on number of users)
  • Total Recognition: ~100-200ms per attempt
  • With Motion Detection: Only processes ~20% of frames (80% optimization)

Why This Approach Works

  • Deep Learning: ResNet model trained on millions of faces
  • 128D Space: High-dimensional space captures facial nuances
  • Distance Metric: Euclidean distance measures similarity effectively
  • Multiple Encodings: 10 encodings per user handle variations

11. Scalability for Large Organizations

Current Limitations

  • ⚠️ File-based Storage: Pickle files in local directory
  • ⚠️ Single Machine: Runs on one computer/Raspberry Pi
  • ⚠️ Linear Search: Compares against all users sequentially
  • ⚠️ No Centralized Database: Each location has separate user database

Scaling Solutions

1. Database Migration

PostgreSQL/MySQL

Store encodings in database with indexing. Supports thousands of users.

MongoDB

Document-based storage. Good for flexible schemas and horizontal scaling.

Redis

In-memory database for fast lookups. Cache frequently accessed users.

2. Optimized Matching Algorithms

  • Vector Similarity Search: Use specialized databases (Pinecone, Weaviate, Milvus)
  • Approximate Nearest Neighbor (ANN): Fast similarity search for large datasets
  • Indexing: Create indexes on face encodings for O(log n) search
  • Clustering: Group similar faces to reduce search space

3. Distributed Architecture

Central Server: Stores all user encodings in database
Edge Devices: Raspberry Pi at each door/entrance
API Communication: Edge devices query central server via REST API
Load Balancing: Distribute requests across multiple servers
Caching: Cache frequently accessed users at edge devices

4. Performance Optimizations

  • Batch Processing: Process multiple faces simultaneously
  • GPU Acceleration: Use GPU for face encoding (10-50x faster)
  • Pre-filtering: Quick checks before expensive matching
  • Connection Pooling: Reuse database connections

12. Door Control Integration

System Overview

The face recognition system can be integrated with physical door locks for automated access control. When a user is authenticated, the system triggers a door unlock mechanism.

Hardware Components

🔌 Raspberry Pi

Runs the face recognition software and controls GPIO pins

⚡ Relay Module

Acts as a switch to control high-voltage door lock (12V/24V)

🔒 Door Lock

Solenoid lock, electric strike, or motorized lock

📷 Camera Module

USB webcam or Raspberry Pi Camera Module

How GPIO Works

GPIO (General Purpose Input/Output): Physical pins on Raspberry Pi
Can be set to HIGH (3.3V) or LOW (0V) via code
GPIO pin → Relay module → Door lock
Code controls GPIO → Relay switches → Door unlocks/locks

Integration Flow

Face Recognition System
    ↓
"ACCESS GRANTED" detected
    ↓
GPIO.setup(18, GPIO.OUT)        # Configure pin 18
GPIO.output(18, GPIO.HIGH)      # Set HIGH = unlock door
    ↓
Wait 5 seconds (door stays unlocked)
    ↓
GPIO.output(18, GPIO.LOW)       # Set LOW = lock door
    ↓
Door locked again

Wiring Diagram

Raspberry Pi          Relay Module          Door Lock
───────────          ───────────          ─────────
GPIO 18 ────────────► IN (Signal)         ────────
GND    ────────────► GND                   ────────
                      COM ────────────────► Lock (+)
                      NO  ────────────────► Lock (-)
                      12V Power Supply

Safety Features

  • Auto-Lock: Door automatically locks after timeout (e.g., 5 seconds)
  • Manual Override: Physical key or button for emergency access
  • Status LED: Visual indicator of lock state (green=unlocked, red=locked)
  • Buzzer/Beep: Audio feedback when door unlocks
  • Fail-Safe: Power loss = door locks (security)

Implementation Approach

Option 1: Direct GPIO Control

  • Use RPi.GPIO library in Python
  • Direct control of GPIO pins
  • Simple and reliable
  • Requires running on actual Raspberry Pi

Option 2: MQTT/HTTP API

  • Face scanner sends unlock command via MQTT/HTTP
  • Separate service on Pi handles GPIO
  • Allows remote control and monitoring
  • Better for distributed systems
